# AGENTS.md

Working guide for AI agents (and humans) contributing to **Noble Notations**.
This file is the single source of truth for conventions; `CLAUDE.md` points
here.

## What this is

Noble Notations is a personal food-research site — primarily biltong
experiment logs, with a `recipe_tinkering` section. It is a
[Docusaurus](https://docusaurus.io/) "classic" static site. There is no
application code: content lives in Markdown, presentation is theme config
plus a small CSS override.

## Stack

- **Docusaurus** 3.10.x (`classic` preset, docs-only — `blog` disabled)
- **React** 19
- **TypeScript** 5.9 (config/typecheck only; not compiled to output)
- **pnpm** is the package manager — see `packageManager` in `package.json`
- Deployed on **Vercel** (`vercel.json`); CI runs on **GitHub Actions**

## Commands

```bash
pnpm install          # install dependencies
pnpm start            # local dev server with hot reload
pnpm build            # production build into ./build (broken links fail)
pnpm serve            # serve the production build locally
pnpm typecheck        # tsc, no emit
pnpm lint             # ESLint
pnpm format           # Prettier write
pnpm format:check     # Prettier check (CI uses this)
```

## Repository layout

```
docs/                     # all site content (routeBasePath is '/')
  index.md                # site landing page (slug: /)
  Biltong.md              # biltong overview
  biltong_logs/           # per-batch experiment logs (batch2..batch6)
  recipe_tinkering/       # experimental recipes
src/css/custom.css        # theme overrides (black + purple)
docusaurus.config.ts      # site + theme configuration
sidebars.ts               # sidebar (autogenerated from docs/ structure)
static/                   # static assets served as-is
.github/workflows/ci.yml  # regression gate
```

## Content conventions

- Content is **Markdown in `docs/`**. The sidebar is autogenerated from the
  folder structure, so file/folder placement controls navigation.
- Use front matter to control ordering and labels:
  ```md
  ---
  sidebar_position: 2
  sidebar_label: Batch 6
  ---
  ```
- Group a section with a `_category_.json` file (see
  `docs/biltong_logs/_category_.json`).
- Keep biltong batch logs consistent: date, weight, cure/spice mix,
  measurements, and outcome. Prefer the same field order across batches.
- Run `pnpm format` before committing — Prettier checks Markdown too
  (`proseWrap` is `preserve`, so prose lines are not reflowed).

## Theme

The site is **dark-first** (`colorMode.defaultMode: 'dark'`) with a
black + purple identity. All colors are CSS variables in
`src/css/custom.css` — adjust them there, in both the `:root` (light) and
`[data-theme='dark']` blocks. Avoid hard-coding colors elsewhere.

## Quality gates

`.github/workflows/ci.yml` runs on every push and PR and must stay green:
format check → lint → typecheck → production build. The build is the real
regression guard — broken internal links fail it (`onBrokenLinks: 'throw'`).
Before pushing, run `pnpm format:check && pnpm lint && pnpm typecheck && pnpm build`.

## Do not touch

- `.claude/` and `.planning/` are managed by the GSD tooling — do not
  hand-edit or reformat them (they are excluded from Prettier and ESLint).
- Do not commit `build/` or `.docusaurus/` (already git-ignored).
